#+title: Readme

Gundroid = Guix + Android ♥

* Description
This channel packages the [[https://developer.android.com/studio][Android Studio]] IDE, the
[[https://developer.android.com/studio/run/emulator][Android emulator]], and the
[[https://developer.android.com/studio/command-line][SDK command-line tools]] for GNU Guix.

There are two ways to use it:

1. *Android Studio in an FHS container* (recommended) — Studio downloads and
   runs its own SDK and emulator inside a Guix sandbox. This is the path that
   "just works": the sandbox provides a normal FHS filesystem, so the prebuilt
   Google binaries (emulator, adb, aapt2, …) find the loader and libraries they
   expect. Modelled on how ~steam~ is packaged in [[https://gitlab.com/nonguix/nonguix][nonguix]].
2. *Standalone SDK packages* — the emulator and SDK tools packaged
   individually, assembled into an ~ANDROID_HOME~ you can drive from the
   command line inside a ~guix shell --emulate-fhs~ environment.

Originally based on Julien Lepiller (@roptat)'s
[[https://lepiller.eu/en/running-android-studio-on-guix.html][blogpost]] and his
[[https://framagit.org/tyreunom/guix-android][guix-android]] channel; the container approach follows
[[https://gofranz.com/blog/react-native-android-on-guix-without-docker/][gofranz's write-up]].

* Android Studio (recommended)
Android Studio is packaged via ~(nonguix multiarch-container)~, the same
technique used for ~steam~.

Install:
#+begin_src sh
guix package -L src -f src/gundroid/studio.scm
#+end_src

Run:
#+begin_src sh
android-studio
#+end_src

On first launch Studio's setup wizard downloads the SDK, a platform, and (if you
create a virtual device) the emulator + a system image. Everything is written to
the sandbox home =~/.local/share/guix-sandbox-home= (the real =$HOME= is *not*
visible inside the container), so your host home stays clean.

You can create an AVD and run the emulator directly from Studio. Requirements:
- Enable hardware virtualization (VT-x/AMD-V) in your BIOS.
- =/dev/kvm= must exist and be accessible (be a member of the =kvm= group); it is
  shared read-write into the container.
- A GPU device (=/dev/dri=) is shared for accelerated rendering.

You do *not* need the ~libvirt~ service for Studio's own emulator — it uses KVM
directly. (You still need ~libvirt~ if you want other virtualization tooling.)

* Standalone SDK / emulator
The prebuilt SDK components are packaged in
~(gundroid packages cli-tools)~ and ~(gundroid packages emulator)~ and assembled
into a standard ~ANDROID_HOME~ layout by ~(gundroid emulator) android-sdk~:

#+begin_example
cmdline-tools/latest/bin/   sdkmanager, avdmanager, apkanalyzer, lint, retrace
platform-tools/             adb, fastboot, etc1tool, logcat
build-tools/34.0.0/         aapt2, apksigner, zipalign
emulator/                   emulator, mksdcard
#+end_example

Build the assembled SDK:
#+begin_src sh
guix build -L src -e '(@ (gundroid emulator) android-sdk)'
#+end_src

These are dynamically-linked prebuilt binaries, so run them inside a Guix FHS
container. The following is verified to work — ~adb~, ~aapt2~, ~sdkmanager~,
~avdmanager~ and the ~emulator~ all run, and ~emulator -accel-check~ confirms
KVM is usable inside the container:
#+begin_src sh
SDK=$(guix build -L src -e '(@ (gundroid emulator) android-sdk)')
guix shell -L src --container --emulate-fhs --network --expose=/dev/kvm \
  coreutils bash grep sed which findutils procps \
  openjdk gcc-toolchain zlib glibc mesa vulkan-loader pulseaudio alsa-lib \
  -e '(@ (gundroid emulator) android-sdk)' \
  -- env ANDROID_HOME="$SDK" ANDROID_SDK_ROOT="$SDK" bash
# inside the shell:
#   adb version
#   aapt2 version
#   $ANDROID_HOME/emulator/emulator -accel-check
#   $ANDROID_HOME/cmdline-tools/latest/bin/sdkmanager --sdk_root=$ANDROID_HOME --list
#+end_src

Two caveats for the standalone SDK:
- ~sdkmanager~ needs an explicit ~--sdk_root=$ANDROID_HOME~ because the
  ~cmdline-tools/latest~ symlink points into the store, so it cannot infer its
  own location.
- The assembled ~android-sdk~ is a *read-only* store directory, so ~sdkmanager~
  cannot install additional packages (system images, platforms) into it, and you
  cannot boot a full AVD from it. For a mutable SDK and to actually boot a
  virtual device, use Android Studio (above) — which downloads a writable SDK
  into its sandbox home — or copy this tree to a writable location first.

The emulator can also be built and run on its own:
#+begin_src sh
guix build -L src -f src/gundroid/packages/emulator.scm
#+end_src

* Status
Verified programmatically (built + run inside a Guix FHS container):
- [X] cli-tools (sdkmanager, avdmanager, apkanalyzer, lint, retrace)
- [X] emulator (~emulator -version~, ~emulator -accel-check~ → KVM usable)
- [X] build-tools (aapt2, apksigner, zipalign)
- [X] platform-tools (adb, etc1tool, fastboot, logcat)
- [X] ~ANDROID_HOME~ assembly (~(gundroid emulator) android-sdk~)
- [X] Android Studio container builds; launching it starts the JVM and the
  IntelliJ platform (a headless run stops at "Unable to detect graphics
  environment", i.e. only the missing display). Run it from a graphical session
  to get the UI, then use its built-in SDK Manager / AVD Manager to download a
  platform + system image and boot the emulator (KVM and ~/dev/dri~ are shared
  into the sandbox).
